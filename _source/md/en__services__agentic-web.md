What we deliver

## What an agentic web   layer includes

Six components. One coherent layer. Everything an AI agent needs to find your business, read it correctly and call it directly.

/agent

##### Agent page

A machine-readable page with structured data formatted for agent discovery and citation.

/llms.txt

##### llms.txt

The index agents look for first — what your site contains and where the canonical answers live.

schema.org

##### Structured data

Organisation, service, product and FAQ markup across the site, so facts are unambiguous.

/.well-known

##### API catalogue

A public catalogue so agent orchestration systems can discover and interact programmatically.

/api/v1

##### Public REST API

A lightweight, read-only API exposing your key data — always accurate, always structured.

/mcp

##### MCP server

So Claude, ChatGPT and any MCP-capable agent can call your data directly as a tool.

How we measure it

## Measured three ways.  Not just claimed.

Most agent-readiness claims stop at “we added an llms.txt”. We prove the layer works with three independent checks, run before and after every build.

01 · Google PageSpeed Insights

##### Agentic Browsing

Can an AI agent reliably understand and navigate your normal website? Agentic Browsing is one of the five categories in a PageSpeed Insights report, and it scores three checks:

- Accessibility tree is well-formed
- Cumulative Layout Shift
- llms.txt follows recommendations

Reported as a score out of 3.

02 · Five AI platforms

##### Independent LLM audits

We give Claude, ChatGPT, Gemini, Grok and Perplexity one prompt and no other context: “Go to yourdomain.com and tell me if the website is LLM/AI/Agent friendly.” Each answer is the platform’s own assessment of which parts of the layer it can find and use: llms.txt, the /agent page, ai.txt, robots.txt, OpenAPI, the public REST API and the MCP server.

Reported as each platform’s verdict, plus the components it confirmed.

03 · Live MCP test

##### An agent takes action

Reading is only half the job. We ask a real AI agent to act for a user through the MCP server and send an enquiry or a quote request, only after the user gives explicit consent. Then we confirm it landed in your normal systems, such as e-commerce orders or the contact form database, ready for sales.

Reported as leads delivered, end to end.

Common questions

## Answers before you ask

What is the agentic web?

The agentic web is the machine-facing layer of a website. It presents the same business information as structured, readable data so AI assistants and agentic browsers can retrieve it, cite it and act on it without parsing a page built for human eyes.

How is this different from SEO or GEO?

SEO and GEO influence whether you are found and recommended. The agentic web decides what an agent can actually read and do once it arrives. They are complementary: visibility brings the agent, the agentic layer serves it.

Do we need to rebuild our website?

No. The agentic layer is added alongside your existing site. Your human website stays exactly as it is; we build a parallel machine-readable layer on the same domain.

How long does an agentic web build take?

A standard build runs about three weeks from audit to verified deployment. Larger sites with multiple markets or product catalogues take longer, mostly in data mapping.

Why does it need monthly upkeep?

Your website keeps changing, new crawlers and browser agents keep arriving, and the specifications themselves are still moving. Without upkeep the layer drifts out of sync and agents answer from stale data.

How do you measure whether it worked?

Four measures: the Lighthouse agentic browsing category, how well leading models describe your business when asked, agent and crawler traffic in your logs, and citation appearances in AI answers.
